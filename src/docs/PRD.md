## 0. 这份文档怎么读（给甲方的一段话）

您要做的东西，本质上是一本**「能搜索、能试算、能改内容的 Excel 函数在线词典」**。

它不是 Excel 插件，不用安装，就是一个网址。用手机或电脑打开浏览器就能用；以后想变成手机 App，也不用重写，因为我们已经把「内容」和「界面」分开放了，**换一层壳就能打包成 App**。

整份文档里凡是出现不好懂的词，我都用大白话解释了一遍。您只需要重点看第 2、3、4、7 章，其余交给开发即可。

## 1. 背景与原始需求复述

### 1.1 背景
甲方为个人用户，日常使用**中文版 Excel**，不具备软件开发背景。核心痛点是：Excel 函数太多、参数记不住、报错信息看不懂，网上查到的资料要么零散、要么只讲概念不讲「填错会怎样」。

### 1.2 原始需求（原话转述）
> 做一个工具，能清晰展示 Excel 里每个函数的使用方法和注意事项。

### 1.3 已确认的范围共识
| 项 | 结论 |
| --- | --- |
| 产品形态 | 网页（响应式，手机 / 平板 / 电脑通用），架构预留 App 化 |
| 使用对象 | 甲方自用为主，可生成链接或导出文件分享给同事朋友 |
| 收录范围 | 第一版 **60 个 Excel 核心函数**，中文名为主、英文对照 |
| 内容维护 | 团队出初稿，甲方**可在网页上直接编辑**，改动**存本机浏览器**，支持**一键导出备份、导入恢复** |
| 核心功能 | 仅两项：**在线试算**、**一键复制可直贴 Excel 的示例** |

## 2. 产品目标

### 2.1 一句话目标

> **让不懂函数的人，在 30 秒内找到对的那个函数，看懂参数怎么填，复制过去就能用，用错了也知道错在哪。**

### 2.2 三条子目标

| 编号 | 目标 | 衡量标准（怎么算做到） |
| --- | --- | --- |
| G1 | **找得到** | 用户从打开页面到进入目标函数详情页，平均不超过 3 次点击；支持中文名、英文名、拼音首字母、用途描述四种找法 |
| G2 | **看得懂、用得上** | 每个函数详情页固定 6 个板块，至少 2 个真实业务示例；示例支持一键复制，粘贴进 Excel 后**无需二次修改即可算出结果** |
| G3 | **敢试错** | 在线试算可自由填参数，能主动触发并解释 `#N/A`、`#VALUE!`、`#REF!` 等常见报错，让用户知道报错是什么意思、怎么修 |

### 2.3 明确的「不做清单」（本期范围之外）

以下内容**第一版不做**，也不预留入口，避免分散注意力：

- ❌ 用户账号 / 登录注册 —— 打开即用，不需要注册
- ❌ 收藏夹、个人笔记、学习进度、测验练习
- ❌ 云端同步（数据只存在本机浏览器里）
- ❌ 深色模式、主题切换
- ❌ 评论区、点赞、社区投稿
- ❌ Excel 插件 / 加载项

## 3. 目标用户与使用场景

### 3.1 用户画像

| 类型 | 描述 | 主要诉求 |
| --- | --- | --- |
| **主要用户** | 甲方本人，非技术岗，日常用中文版 Excel 处理工作数据 | 记不住函数名和参数顺序，需要一个「随时能查、能抄、能试」的地方 |
| **次要用户** | 甲方分享链接后的同事、朋友 | 收到链接直接打开，无需安装 / 注册，看懂一个函数即可离开 |
| **潜在用户** | 刚接手数据工作的职场新人、需要辅导同事的团队负责人 | 用现成示例解释「为什么这个公式这么写」 |

### 3.2 三个生活化使用场景

**场景一：两张表对不上，记不清 VLOOKUP 第 4 个参数该填 0 还是 1**

> 小李手上有两张表：一张是「员工工号 + 姓名」，一张是「工号 + 本月业绩」。他要把业绩并到第一张表里。他记得要用 VLOOKUP，但每次都不确定最后那个参数是填 `0` 还是 `1`，也不确定填错了会怎样。
>
> **本产品怎么解决：** 手机搜「zxcx」（纵向查找拼音首字母）或「两个表匹配数据」，直接进 VLOOKUP 页。参数说明里明确写「第 4 个参数：填 0 = 精确匹配（找不到就报错）；填 1 或省略 = 模糊匹配（要求第一列已排序，否则结果可能是错的）」。试算区里点一下「如果我填 TRUE 会怎样」，立刻看到返回了一个错误的人名，配上解释。看完心里有数了。

**场景二：领导要「华东区、且销售额大于 10 万、且已回款」的总数**

> 小李知道 SUMIF 只能加一个条件，多个条件要用 SUMIFS，但每次都搞反参数顺序——是先写求和区域，还是先写条件区域？
>
> **本产品怎么解决：** 详情页把「语法结构」做成带占位符的一行公式，鼠标点每个参数会在下面高亮对应说明。试算区预填了条件，改数字实时看结果。看完点「复制公式 + 示例数据」，直接粘进 Excel，改一下单元格范围就能用。

**场景三：日期在 Excel 里变成了一串数字，或者「2024-01-05」算不出天数差**

> 小李从系统导出的表里，日期是文本格式，VLOOKUP 怎么都匹配不上。他需要一个能说清楚「为什么」的地方。
>
> **本产品怎么解决：** TEXT / DATEVALUE / DATE 页面里，「常见错误与注意事项」板块专门写了「看起来是日期、其实是文本，怎么办」，并给出 `=DATEVALUE(A2)` 或「分列」两种解法。试算区可以故意把日期写成文本，看到 `#VALUE!` 报错长什么样。

### 3.3 用户旅程（Happy Path）

```
打开网址
  ↓
首页搜索框输入「两个表匹配数据」 或 点「查找与引用」分类
  ↓
列表页看到「纵向查找 VLOOKUP」+ 一句话用途
  ↓
详情页：一句话用途 → 语法 → 参数 → 示例（点「复制」）→ 注意事项
  ↓
试算区：改参数看结果 / 故意填错看报错
  ↓
粘贴进 Excel，完事
```

## 5. 页面结构与信息架构

### 5.1 站点地图

```
Excel 函数速查（全部采用 hash 路由，详见下方说明）
│
├── 首页 /#/                           —— 搜索 + 分类导航 + 最近浏览（P1）
│
├── 分类列表页 /#/category/:id         —— 某一类下的函数清单
│   └── 搜索结果页 /#/search?q=        —— 复用列表页布局
│
├── 函数详情页 /#/f/:id                —— 核心页面（6 板块 + 试算区 + 编辑模式）
│   ├── ① 一句话用途
│   ├── ② 语法结构
│   ├── ③ 参数逐项说明
│   ├── ④ 真实示例（一键复制）
│   ├── ⑤ 常见错误与注意事项
│   ├── ⑥ 相关函数推荐
│   └── 【在线试算区】（常驻，含免责声明）
│
├── 数据管理页 /#/data                 —— 导出备份 / 导入恢复 / 恢复官方原文
│
└── 关于页 /#/about                    —— 产品说明、免责声明、版本信息
```

> ⚠️ **【开发前必须定死】为什么所有路径都带 `#`（hash 路由）**
>
> 本项目是**纯静态网页、没有后端服务器**（见 P0 及 10.1）。如果做成 `/f/vlookup` 这种普通路径，服务器上并不存在这个文件夹，用户把这个链接发给同事、对方打开或刷新就会直接 **404（页面不存在）**。
>
> `#` 后面的内容不会发送给服务器，浏览器自己就能定位，因此**在任何静态托管上都能 100% 打开**，不需要额外配置。
>
> **代价**：链接里多一个 `#`（`xxx.com/#/f/vlookup`），观感上略逊于纯路径。
> **结论**：兼容性优先，采用 hash 路由。**此项必须在开发启动前确定，后期改路由成本很高。**
>
> 📘 **人话解释**：就像一本书的页码。`#` 后面的部分是"你自己翻到第几页"，不用问服务器要；没有 `#` 的话，服务器会以为你要一本叫 `f/vlookup` 的书，找不到就给你一个 404。

**搜索命中排序规则（P0，必须实现，否则拼音撞车时体验混乱）**

60 个函数里存在**拼音首字母完全撞车**的情况（例如「与 AND / 右 RIGHT / 月 MONTH」的首字母都是 `y`）。如果下拉结果的排序是随机的，用户会以为「搜索坏了」。因此结果必须严格按以下 6 级排序：

| 优先级 | 命中方式 | 举例 |
| --- | --- | --- |
| ① | 输入与**英文名**完全相等（不区分大小写） | 输入 `vlookup` |
| ② | 输入与**中文名**完全相等 | 输入 `纵向查找` |
| ③ | **中文名全拼**前缀匹配（`pinyinFull`） | 输入 `zongxiang` |
| ④ | **拼音首字母**完全相等（`pinyinInitials`） | 输入 `zxcz` |
| ⑤ | **英文名**前缀匹配 | 输入 `vlook` |
| ⑥ | 别名 / 用途关键词包含匹配（`alias` / `keywords`） | 输入 `两个表匹配数据` |

**两条硬约束**：

1. **单字母缩写（`y` / `z` / `n` / `r` / `f` / `h`）不得作为高置信命中**，必须排在全拼匹配（③）之后。否则用户打一个字母会弹出一大片无关函数。
2. 下拉每条结果**必须同时显示「中文名 · 英文名 · 一句话用途」三要素**，让用户自己一眼分清——撞车本身不可怕，分不清才可怕。

> 📘 **为什么这条重要**：用户是「记不清名字」才来搜的，搜索是这个产品的入口。入口一旦给人「搜不准」的印象，后面 6 个板块做得再好也白搭。

## 6. 函数详情页的字段定义（数据结构草案）

> 这一章是给开发和架构师看的。甲方只需要知道：**每个函数在电脑里就是一段结构化的文字**，改内容就是改这段文字；导出备份导的就是这段文字。

### 6.1 设计原则

1. **内容与界面分离**：所有函数内容都是纯数据（见下方 JSON），界面只负责「读数据 → 渲染」。将来做 App，直接换一层界面即可，数据不动。
2. **一份数据两种用途**：同一份数据既渲染详情页，也驱动「在线试算」和「一键复制」，避免三处维护。
3. **可降级**：任何字段缺失都不应该导致页面崩溃，缺失板块显示「待补充」。

### 6.4 「一键复制」的两种载荷

| 按钮 | 复制到剪贴板的内容 | 粘贴到 Excel 的效果 |
| --- | --- | --- |
| **复制公式** | 纯公式文本，如 `=VLOOKUP(F2,$A$2:$C$4,2,0)` | 只粘一个公式，自己改引用 |
| **复制公式 + 数据** | 先一段 TSV 数据（表头 + 3 行），**空一行**，再一行公式 | 数据自动分列到 A/B/C 列，公式落在指定单元格，立即算出结果 |

> **说明**：TSV =「用 Tab 分隔的文本」，是 Excel 剪贴板的原生格式，粘贴时会自动分成多列。复制后顶部提示「已复制，去 Excel 里按 Ctrl+V」。

### 6.5 在线试算的实现口径（给开发的技术约定，甲方可略读）

- 试算引擎采用**开源公式解析库**（如 HyperFormula / Formula.js），在浏览器本地运行，不发请求、不传数据。
- 引擎覆盖 Excel 主流函数语法与错误类型（`#N/A`、`#VALUE!`、`#REF!`、`#DIV/0!`、`#NAME?`、`#NUM!`），错误码由引擎原生抛出，页面只负责翻译成人话。
- **不追求 100% 一致**：区域设置（日期格式、列表分隔符）、日期序列号起点、浮点精度等边缘情况可能有细微差异。因此试算区必须常驻免责声明。
- 每个函数的 `playground.cases` 里的 `expect` 值，开发交付前需在**真实中文版 Excel** 中逐一验证一遍，验证不通过的在函数页标注「本函数试算为近似实现」。

### 7.13 ⚠️ 中文名实测核对清单（内容生产启动前必须完成）

**背景**：本产品要按「中文名为主、英文对照」呈现（如「纵向查找 VLOOKUP」）。但有一个**必须先说清、否则会误导甲方的事实**：

> **微软中文版 Excel 里，函数名称始终是英文的。** 在单元格里必须输入 `=VLOOKUP(...)`；输入 `=纵向查找(...)` 只会得到 `#NAME?`。
> Excel 中文版只把「分类名」和「函数说明文字」翻译成了中文，**函数名本身不做本地化**（自 Excel 2010 起各语言版本统一使用英文函数名）。
>
> **唯一例外是 WPS 表格**：WPS 支持中文函数名（可输入 `=纵向查找()`、`=求和()`），这是 WPS 的特色功能，与 Excel 不互通。

**因此「中文名」在产品里的定位必须明确**（这是整个命名策略的地基）：

> **中文名 = 帮你理解和搜索的「助记名」，不是让你往 Excel 里输入的名字。往 Excel 里输入的永远是英文名。**
>
> 这一条必须在**首页顶部**和**每个详情页的函数名旁边**用一句话说清楚，否则甲方照着中文名往 Excel 里敲，只会得到一堆 `#NAME?`，反而会觉得工具不准。

**统一处理原则（已定稿）**：

> - **主显示统一为「中文助记名 + 英文名」，英文名为正式可复制名称**：如「纵向查找 `VLOOKUP`」。界面上英文名用等宽字体 + 可点击复制，强化「这个才是要敲进 Excel 的」。
> - **中文助记名沿用国内通用叫法**（如「纵向查找」「多条件求和」「条件判断」），**不追求「官方译名」——官方没有中文函数名**。
> - 新函数中**国内尚无通用叫法**的（如 XLOOKUP、UNIQUE、TEXTJOIN、IFS），**英文名为主显示**，中文俗称降级进 `alias` 搜索索引，避免我们自造一个甲方没听过的名字。
> - 59 号 `CONVERT`、60 号 `DSUM` 同理，中文名仅作助记。
> - **WPS 用户提示**（仅当甲方确认用 WPS 时显示）：WPS 支持中文函数名，但与其他表格软件不互通，**建议统一使用英文名**。

> 📘 **这条修正了原稿的一处错误**：原文写「本产品以『中文版 Excel 里显示的就是中文名』为核心立论」——这是不成立的，Excel 中文版不显示中文函数名。原稿把「6 个函数存疑」当成本地化差异处理，方向偏了；真实情况是**全部 60 个函数名在 Excel 里都是英文**，存疑的只是「中文助记名该用哪个叫法」。

既然 Excel 里函数名统一是英文，甲方要核的就只剩两件事：**① 中文助记名叫法顺不顺耳；② 这个函数在他的 Excel 版本里存不存在。**

**① VLOOKUP 纵向查找**

| 项 | 内容 |
| --- | --- |
| 试算参数 | 查找值 / 查找区域 / 返回第几列 / 匹配方式（0 精确、1 大致） |

| 示例 2 | 用 IFERROR 包一层，查不到时显示「无此人」 |
| 示例 3 | 区域加 `$` 绝对引用后向下填充（讲清不加 `$` 会怎样） |

| 项 | 内容 |

| 示例 2 | **从右往左查**（VLOOKUP 做不到，这是它的杀手锏） |
| 示例 3 | 第 4 参数自定义「未找到」提示，替代 IFERROR 包裹 |
| **错误演示（≥3）** | ① 查找列与返回列**行数不一致** → `#VALUE!` ② 在 Excel 2016/2019 里输入 → `#NAME?`（版本不支持）③ 不填第 4 参数且查不到 → `#N/A` ④ 匹配模式选「二分查找」但数据没排序 → **结果错且无报错** |
| 相关函数 | VLOOKUP（被替代，易混淆）/ FILTER（要返回多行时用它）/ IFERROR（常搭配，但 XLOOKUP 自带兜底后可不配）/ INDEX+MATCH（老版本替代方案） |

**⑤ TEXT 文本格式化**

| 项 | 内容 |
| --- | --- |
| 试算参数 | 要格式化的值 / 格式代码 |
| 示例 1 | 日期 → 「2024年03月」（报表标题） |
| 示例 2 | 数字 → 保留两位小数 + 千分位 + 百分号 |
| 示例 3 | 数字 → 补前导零（工号 `7` 显示成 `007`） |
| **格式代码速查小表** | 本函数**必须额外附一张**常用格式代码对照表：`yyyy` / `mm` / `dd` / `m月` / `yyyy年mm月` / `0.00` / `#,##0` / `0.0%` / `000` 等 **≥ 10 行**。这是 TEXT 最常被查的东西 |
| **错误演示（≥3）** | ① 格式代码用了**中文引号或全角字符** → `#VALUE!` 或结果不对 ② 格式代码**忘了加引号** → `#NAME?` ③ `mm`（两位月）与 `mmm`（英文月份缩写）分不清 → 结果不对 ④ 把「单元格格式」那套设置当成格式代码填进去 → 结果不对 ⑤ 中文区域代码（如 `[$-zh-CN]`）在不同电脑上表现不一致 |
| 相关函数 | VALUE（反向：文本转数字，易混淆）/ LEFT、MID（截取，常搭配）/ DATE（构造日期）/ TEXTJOIN（合并时顺便格式化） |

> **样板确认会的建议议程（甲方验收时用）**：逐个打开 5 个页面，**只问三个问题**——
> ① 这段话你能一眼看懂吗？② 这个示例跟你的实际工作像不像？③ 在试算区随便改两个数，结果和你在 Excel 里试的一样吗？
> 三个都点头，再启动剩下 55 个的批量生产。

### 10.5 内容生产 SOP（55 个函数批量补齐的统一口径）

> **为什么要有这一节**：甲方验收的第一条就是「**写法是否一致**」。没有 SOP，多人写 414 个函数会写出多种风格，必然大返工。本节在**批量生产之前**定稿。

**10.5.1 统一业务数据（跨函数复用，降低认知负担）**

所有示例**只允许使用这 3 张表**，禁止每个函数自造一套数据：

| 表名 | 字段 | 行数 |
| --- | --- | --- |
| 员工表 | 工号 / 姓名 / 部门 / 入职日期 / 月薪 | 8 行 |
| 销售表 | 日期 / 销售员 / 区域 / 产品 / 数量 / 金额 / 是否已回款 | 12 行 |
| 考勤表 | 工号 / 姓名 / 日期 / 上班打卡 / 下班打卡 / 是否迟到 | 10 行 |

> 📘 **为什么**：用户看第二个函数时不用再重新理解一遍示例背景，注意力全部放在公式上。

**10.5.2 各板块写作规范**

| 板块 | 规范 |
| --- | --- |
| ① 一句话用途 | ≤ 20 字；**以动词开头**（把 / 算 / 找 / 判断 / 去掉 / 合并…）；**禁止**「用于……」这类官方腔；**禁止**照抄微软定义 |
| ② 语法结构 | 两行：上行中文占位符（`=VLOOKUP(找什么,在哪找,第几列,匹配方式)`），下行英文原式。**选填参数必须用 `[ ]` 包起来** |
| ③ 参数说明 | 每个参数固定 4 要素：填什么 / 能填什么（枚举常见取值）/ 不填会怎样 / 填错会怎样。参数超过 4 个时**必须**标注「最常填错的是第 X 个」 |
| ④ 示例 | 每例固定 5 件套：场景一句话 → 数据小表格 → 公式 → 结果 → 一句话记忆点。数据表格**必须**完整可粘贴（含表头），**禁止**只给一句光秃秃的公式 |
| ⑤ 注意事项 | ≥ 3 条；每条固定句式：**错在哪 → 为什么会错 → 怎么改**。错误值用等宽红字。**优先收录「不报错但结果错」的坑**（比报错更危险） |
| ⑥ 相关函数 | 3–5 个，每个标注关系类型：**易混淆** / **可替代** / **常搭配**，并写一句「什么时候该用它而不是这个」 |

**10.5.3 禁止事项（内容层面）**

- 禁止出现「众所周知」「显而易见」这类废话
- 禁止出现未经解释的英文术语缩写（如「通配符」要顺带说明 `*` 和 `?` 怎么用）
- 禁止把示例写成 `=SUM(A1:A10)` 这种**无业务含义的占位**
- 禁止在注意事项里写「详见微软官方文档」——用户就是不想看官方文档才来的

**10.5.4 交付与抽检**

- 每批交付 **15 个**，分 4 批走完 55 个
- 每批抽检 **3 个**（第 1 个、中间 1 个、最后 1 个），按本节 SOP 逐条打分，**不合格整批退回**
- 甲方每批只确认一次，避免反复打断
- 每批交付时附带一句「你还想要哪个函数？」，由甲方从备选池（7.12）点名补充，比我们替他猜更准
