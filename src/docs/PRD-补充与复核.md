## 2. 数据缺陷修正

### 2.1 【D-01】拼音首字母冲突表（必须修正，否则搜索失灵）

**问题**：60 个函数里有 3 组拼音首字母完全撞车，用户输入后会命中多个函数，如果下拉排序没做好，用户会以为"搜索坏了"。

| 冲突组 | 冲突的缩写 | 涉及函数 | 全拼（用于消歧） |
|---|---|---|---|
| 第 1 组 | `y` | 与 AND / 右 RIGHT / 月 MONTH | `yu` / `you` / `yue` |
| 第 2 组 | `z` | 左 LEFT / 中 MID | `zuo` / `zhong` |
| 第 3 组 | `xz` | 现在 NOW / 现值 PV / 选择 CHOOSE | `xianzai` / `xianzhi` / `xuanze` |
| 附带 | `h` | 或 OR / 合并 CONCAT（`hb` 的前缀） | `huo` / `hebing` |
| 附带 | `ss` | 搜索 SEARCH / 是数字 ISNUMBER（`ssz` 的前缀） | `sousuo` / `shishuzi` |
| 附带 | `rq` | 日期 DATE / 日期差 DATEDIF（`rqc` 的前缀） | `riqi` / `riqicha` |

**修正要求（写入开发口径）**：

1. `searchIndex.json` 必须**同时收录首字母与全拼**两个字段，缩写不再是唯一检索键。
   ```
   SearchEntry {
     id         字符串  函数 id
     nameCn     字符串  中文名
     nameEn     字符串  英文名
     abbr       字符串  拼音首字母，如 "xz"
     pinyin     字符串  中文名全拼，如 "xianzai"
     aliases    数组    用途关键词、别名
   }
   ```
2. 搜索命中多个时的**排序规则**（必须实现，否则冲突组体验依然混乱）：
   ```
   ① 输入与「英文名」完全相等（不区分大小写） → 排最前
   ② 输入与「中文名」完全相等
   ③ 「中文名全拼」前缀匹配
   ④ 「拼音首字母」完全相等
   ⑤ 「英文名」前缀匹配
   ⑥ 别名 / 用途关键词包含匹配
   ```
3. 单字母缩写（`y` / `z` / `n` / `r` / `f` / `h`）**不单独作为高置信命中**，必须排在全拼匹配之后。
4. 下拉结果每条都要显示「中文名 · 英文名 · 一句话用途」三要素（PRD §4 P1 已定），让用户自己一眼分清，冲突就不会造成误点。

> 📘 **为什么这件事重要**：甲方是"记不清名字"才来搜的，搜索是这个产品的入口。入口一旦给人"搜不准"的印象，后面 6 个板块做得再好也白搭。

### 2.2 【D-02】中文名二次核对清单（4 个存疑）

**背景**：产品的核心立论是「中文版 Excel 里显示的就是中文名，所以以中文名为主」。但 Excel 对**较晚推出的函数通常不做本地化**（中文版里直接显示英文原名）。PRD §6 中下列 4 条的中文名需要**在甲方自己的中文版 Excel 里实测确认**，否则会出现"按 PRD 写的名字，甲方在自己 Excel 里根本搜不到"。

| # | 函数 | PRD 里的写法 | 存疑点 | 建议处理 |
|---|---|---|---|---|
| 1 | TEXTJOIN | 「文本合并」+ 标注"（沿用英文名）" | **自相矛盾**：既给了中文名"文本合并"，又标了沿用英文名 | 二选一。若中文版显示 `TEXTJOIN`，则改为「TEXTJOIN（中文版不翻译）」，拼音字段只留 `textjoin` |
| 2 | DATEDIF | 「日期差」 | DATEDIF 是 Excel 的**隐藏函数**（函数列表里搜不到、无智能提示），中文版很可能直接显示 `DATEDIF` | 保留中文名"日期差"作为别名，主显示名实测确认；并在页面显著位置提示"这是隐藏函数，需手动完整输入，无输入提示" |
| 3 | EOMONTH | 「月末」 | 中文版可能显示 `EOMONTH` | 实测确认；无论结果如何，中文别名"月末/月底"必须进 `aliases` |
| 4 | CONCAT | 「合并」+ 标注"（沿用英文名）" | 与 TEXTJOIN 同类问题 | 同上，二选一 |

**统一处理原则（建议写入 PRD §6 说明）**：

> 凡是中文版 Excel 不翻译的函数，采用「英文名为主显示 + 中文俗称进别名」：**显示为 `XLOOKUP`**，中文别名"精确查找/高级查找/万能查找"进搜索索引。
> 凡是中文版有官方译名的，**显示为「中文名 + 英文名小字」**，如「纵向查找 VLOOKUP」。
>
> 这样既尊重"甲方在自己 Excel 里看到什么名字"这个前提，又保证口语化搜索仍然可用。

**同时补充一条**：`XLOOKUP` 的拼音字段 PRD 写的是 `jccz`（精确查找），但它标注了"沿用英文名"，两者不一致。按上述原则应改为 `xlookup`，`jccz` 移入 aliases。

## 3. 缺失的 P0 / P1 功能定义（新增，需要并入需求池）

### 3.1 【G-01】F24 · 导出为"能直接给人看"的离线文件 **P1**

**甲方原话**：希望能生成链接 / **导出分享给同事朋友看**。

**PRD 现状**：只有 `/f/{id}` 链接 + 备份用 `.json`。备份 JSON 打开是一堆代码符号，发给同事等于没发。

**补充定义**：

| 项 | 内容 |
|---|---|
| 需求 | 提供「导出为离线网页」：把当前查看的函数（或全部函数）导出成**一个 `.html` 文件**，双击就能用浏览器打开，**不用联网、不用装任何东西** |
| 内容 | 只含只读内容（不含甲方的编辑态、不含编辑按钮），排版与网页一致 |
| 文件名 | `Excel函数速查-VLOOKUP.html` / `Excel函数速查-全集-20240915.html` |
| 优先级 | **P1**（第一版 v1.0 共 414 个函数，分享价值高；**数据结构按"可导出"设计**） |
| 为什么现在要定 | 若数据层把内容和界面逻辑耦合，事后补单文件导出等于重写。这是"预留转 App 能力"的同一条设计纪律 |

> 📘 **人话解释**：相当于把网页"打包进一个文件"，微信发给同事，对方点开就能看，跟打开一个 Word 文档一样简单。

### 3.2 【G-02】F23 · 复制必须输出 TSV 格式 **P0**

**PRD 现状**（F04）："复制整块示例（含数据小表格）…… 复制后能直接粘贴进 Excel 且不串格式"。**没说怎么做**，开发按常规做法（复制纯文本）必然导致：整个表格粘进 Excel 变成**一个单元格**，用户还得手动分列。这直接击穿 G2「抄得走」。

**补充定义**：

| 项 | 内容 |
|---|---|
| 需求 | 「复制整块示例」写入剪贴板的内容必须是 **TSV（制表符分隔的文本）**，而不是网页上的可见文本 |
| 行为 | 表格区：每行一行文本，单元格之间用 `\t` 分隔 → 粘进 Excel 自动分列；公式区：单独一行，以 `=` 开头；表头：一并复制 |
| 复制内容顺序 | ① 示例标题行 → ② 数据小表格（表头 + 数据行）→ ③ 空一行 → ④ 公式 → ⑤ 结果 |
| 降级方案 | 若浏览器不支持富文本剪贴板 API，退化为：弹出一个全选状态的文本框 + 提示"已为你选中，按 Ctrl/⌘+C 复制" |
| 验收标准 | 在 Windows Excel、WPS 表格、Mac Excel 三处各粘贴一次，**都必须自动分列**，不得出现"整块进一个单元格" |

> 📘 **人话解释**：Excel 认识一种特殊格式——单元格之间用「Tab 键」隔开。只要复制的内容是这种格式，粘进去就会自动一格一格排好，不用再点"分列"。

### 3.3 【G-03】F26 · 路由方式约束 **P0**

**问题**：PRD §8.4 定的链接是 `/f/vlookup`（路径式）。但 PRD §N02 又要求"纯静态网页、无后端"。**这两条在技术上冲突**：静态托管服务器上并不存在 `/f/vlookup` 这个文件夹，用户把这个链接发给同事、同事打开或刷新，会直接 **404**。

**补充定义**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 改用 **hash 路由**：`xxx.com/#/f/vlookup` | 任何静态托管都 100% 可用，零配置，兼容性最好 |
| B | 保持路径路由 + 在托管平台配置"所有路径回退到 index.html" | 链接更干净，但换托管平台就要重新配一次，甲方自己部署时容易踩坑 |
| C | 路径路由 + 额外生成静态页面文件 | 60 个函数要生成 60 个文件，构建复杂，不划算 |

**建议**：采用 **方案 A（hash 路由）**。链接形如 `xxx.com/#/f/vlookup`，只比方案 B 多一个 `#`，但换来"传到哪儿都能打开"。**此项需在开发前定死**，后期改路由成本很高。

### 3.4 【G-04】F25 · 移动端 / 微信内置浏览器的复制降级 **P1**

**场景**：甲方的主要分享渠道是微信。同事在微信里点开链接 → 微信内置浏览器 → 点"复制"按钮。这个环境下剪贴板 API 经常被限制，点了没反应，用户会认为产品坏了。

**补充定义**：

| 项 | 内容 |
|---|---|
| 需求 | 检测复制失败时，自动降级为「选中 + 提示」：把要复制的内容填入一个可见文本框并自动全选，上方提示"已为你选中，长按后点『拷贝』" |
| 兜底文案 | 每种环境一句人话提示，不说"剪贴板 API 调用失败"这种话 |
| 优先级 | P1（第一版可用简单检测，不追求覆盖所有机型） |

## 4. 【G-05】5 个样板函数的逐个规格（验收基准）

> **为什么要有这一节**：甲方验收口径是「写法是否一致、详细程度是否合适、试算体验是否顺畅」。不给具体规格，5 个样板做完必然对不齐，甲方一改就是 5 份返工。
> **用法**：这一节直接作为内容生产的**派工单**，一格一格填。

### 通用最低标准（5 个样板全部适用）

| 项 | 指标 |
|---|---|
| 一句话用途 | ≤ 20 字，动词开头 |
| 参数说明 | 每个参数 4 要素齐全（填什么 / 能填什么 / 不填会怎样 / 填错会怎样） |
| 示例数 | **≥ 2 个**（建议 3 个：最常用 / 进阶 / 易错对照） |
| 每个示例 | 场景一句话 + 数据小表格（3–5 行）+ 公式 + 结果 + 一句话记忆点 |
| 注意事项 | **≥ 3 条**，每条按「错在哪 → 为什么会错 → 怎么改」写 |
| 相关函数 | 3–5 个，标注关系（易混淆 / 可替代 / 常搭配） |
| 试算 | 参数控件齐全 + 公式实时回显 + 默认有结果 |
| 错误复现 | **≥ 3 个一键触发场景** |

### ① VLOOKUP 纵向查找

| 项 | 内容 |
|---|---|
| 一句话用途 | 按一个关键值，竖着查表，返回同一行别处的答案 |
| 试算参数 | 要查谁 / 在哪片区域找 / 返回第几列 / 匹配方式（0 精确、1 大致） |
| 示例 1 | 按工号查姓名（最常用，精确匹配） |
| 示例 2 | 按分数段查等级（大致匹配，必须先把首列升序排序） |
| 示例 3 | 跨工作表查，区域加 `$` 绝对引用后向下填充 |
| **错误复现（≥3）** | ① 第 4 参数填 `1` 且首列没排序 → **不报错，但查出来是别人**（最危险的坑，必须做）<br>② 列序号填 `10`（超出区域列数）→ `#REF!`<br>③ 查的值在首列里没有 + 精确匹配 → `#N/A`<br>④ 区域没加 `$`，公式往下拉后区域跟着跑偏 → `#N/A`<br>⑤ 数字被存成了文本（或带前后空格）→ `#N/A` |
| 相关函数 | XLOOKUP（可替代）/ HLOOKUP（横版，易混淆）/ MATCH+INDEX（常搭配）/ IFERROR（包一层防报错） |

### ② SUMIFS 多条件求和

| 项 | 内容 |
|---|---|
| 一句话用途 | 同时满足好几个条件的数字，才加在一起 |
| 试算参数 | 求和区域 / 条件区域1 + 条件1 / 条件区域2 + 条件2 /（可加第三组） |
| 示例 1 | 华东区 且 金额 > 10000 的销售额合计 |
| 示例 2 | 指定日期区间内的回款合计（讲清日期条件的写法） |
| 示例 3 | 条件用单元格引用 + 通配符（`"*东*"`） |
| **错误复现（≥3）** | ① 条件区域和求和区域**行数不一样** → `#VALUE!`<br>② 条件写成 `>1000` **忘了加引号** → 公式报错或结果错<br>③ 文本条件写成 `华东` 不加引号 → `#NAME?`<br>④ 日期直接写 `"2024/3/5"` 文本 → 换台电脑/换区域设置可能算出 0<br>⑤ 想表达"包含东字"却忘了加 `*`，或要查字面量 `*` 时忘了用 `~` 转义 |
| 相关函数 | SUMIF（单条件版，易混淆）/ COUNTIFS（数个数，常搭配）/ SUMPRODUCT（更灵活，可替代）/ DATE（写日期条件） |

### ③ IF 如果

| 项 | 内容 |
|---|---|
| 一句话用途 | 满足条件就给一个结果，不满足给另一个 |
| 试算参数 | 条件 / 成立时返回 / 不成立时返回（可留空） |
| 示例 1 | 成绩 ≥ 60 判"及格"，否则"不及格" |
| 示例 2 | 嵌套三层：≥90 优 / ≥80 良 / ≥60 及格 / 其余不及格 |
| 示例 3 | 与 AND / OR 组合做多条件判断 |
| **错误复现（≥3）** | ① 条件写成 `A1==60`（编程习惯的双等号）→ `#NAME?`<br>② 返回的文字**忘了加引号**（写 `及格` 而非 `"及格"`）→ `#NAME?`<br>③ 多条件写成 `IF(A1>60 AND A1<80, ...)` → `#NAME?`（要用 `AND(...)` 包起来）<br>④ 嵌套层数过深（超过 64 层）→ 公式报错<br>⑤ 第三参数省略且条件不成立 → 返回 `FALSE`，不是空白 |
| 相关函数 | IFS（多条件替代，更清爽）/ AND、OR（常搭配）/ IFERROR（防报错，易混淆）/ SUMIFS（条件求和时别用 IF 硬凑） |

### ④ XLOOKUP

| 项 | 内容 |
|---|---|
| 一句话用途 | VLOOKUP 的升级版：不用数列数、能往左查、查不到可自定义提示 |
| 版本标注 | **必须在页面显著位置标注**：需 Microsoft 365 / Excel 2021 及以上，旧版无此函数 |
| 试算参数 | 要查谁 / 在哪一列找 / 要返回哪一列 / 找不到时显示什么 / 匹配模式 / 搜索模式 |
| 示例 1 | 按工号查姓名（对比 VLOOKUP 同一场景，体现"不用数列数"） |
| 示例 2 | 从右往左查（VLOOKUP 做不到，这是 XLOOKUP 的杀手锏） |
| 示例 3 | 第 4 参数自定义"未找到"提示，替代 IFERROR 包裹 |
| **错误复现（≥3）** | ① 查找列和返回列**行数不一致** → `#VALUE!`<br>② 在 Excel 2016/2019 里输入 → `#NAME?`（版本不支持）<br>③ 不填第 4 参数且查不到 → `#N/A`<br>④ 匹配模式选"通配符"但查找值是数字 → `#N/A`<br>⑤ 匹配模式选"二分查找"但数据没排序 → **结果错但无报错** |
| 相关函数 | VLOOKUP（被替代，易混淆）/ FILTER（要返回多行时用它）/ IFERROR（常搭配，但 XLOOKUP 自带兜底后可不配）/ INDEX+MATCH（老版本替代方案） |

### ⑤ TEXT 文本

| 项 | 内容 |
|---|---|
| 一句话用途 | 按你指定的格式，把数字或日期显示成想要的样子 |
| 试算参数 | 要格式化的值 / 格式代码 |
| 示例 1 | 日期 → "2024年03月"（报表标题） |
| 示例 2 | 数字 → 保留两位小数 + 千分位 + 百分号 |
| 示例 3 | 数字 → 补前导零（工号 `7` 显示成 `007`） |
| **格式代码速查小表** | 本函数**必须额外附一张**常用格式代码对照表：`yyyy`/`mm`/`dd`/`m月`/`yyyy年mm月`/`0.00`/`#,##0`/`0.0%`/`000` 等 ≥ 10 行。这是 TEXT 最常被查的东西 |
| **错误复现（≥3）** | ① 格式代码用了**中文引号或全角字符** → `#VALUE!` 或结果不对<br>② 格式代码**忘了加引号** → `#NAME?`<br>③ `mm`（两位月）和 `mmm`（英文月份缩写）分不清 → 结果不对<br>④ 把"单元格格式"那套设置当成格式代码填进去 → 结果不对<br>⑤ 中文环境下的区域代码（如 `[$-zh-CN]`）在不同电脑上表现不一致 |
| 相关函数 | VALUE（反向：文本转数字，易混淆）/ LEFT、MID（截取，常搭配）/ DATE（构造日期）/ TEXTJOIN（合并时顺便格式化） |

> **样板确认会的建议议程**（甲方验收时用）：逐个打开 5 个页面，**只问三个问题**——
> ① 这段话你能一眼看懂吗？② 这个示例跟你的实际工作像不像？③ 在试算区随便改两个数，结果和你在 Excel 里试的一样吗？
> 三个都点头，再启动剩下 55 个的批量生产。

## 5. 【G-06】内容生产 SOP（55 个函数批量补齐的统一口径）

> **为什么要有这一节**：甲方验收的第一条就是"**写法是否一致**"。没有 SOP，多人写 414 个函数会写出多种风格，必然大返工。这一节在**批量生产之前**定稿。

### 5.1 统一业务数据（跨函数复用，降低认知负担）

所有示例**只允许使用这 3 张表**，禁止每个函数自造一套数据：

| 表名 | 字段 | 行数 |
|---|---|---|
| 员工表 | 工号 / 姓名 / 部门 / 入职日期 / 月薪 | 8 行 |
| 销售表 | 日期 / 销售员 / 区域 / 产品 / 数量 / 金额 / 是否已回款 | 12 行 |
| 考勤表 | 工号 / 姓名 / 日期 / 上班打卡 / 下班打卡 / 是否迟到 | 10 行 |

> 📘 **为什么**：用户看第二个函数时不用再重新理解一遍示例背景，注意力全在公式上。

### 5.2 各板块写作规范

| 板块 | 规范 |
|---|---|
| ① 一句话用途 | ≤ 20 字；**以动词开头**（把/算/找/判断/去掉/合并…）；**禁止**"用于……"这类官方腔；**禁止**照抄微软定义 |
| ② 语法结构 | 两行：上行中文占位符（`=VLOOKUP(找什么,在哪找,第几列,匹配方式)`），下行英文原式。**选填参数必须用 `[ ]` 包起来** |
| ③ 参数说明 | 每个参数固定 4 要素：填什么 / 能填什么（枚举出常见取值）/ 不填会怎样 / 填错会怎样。参数超过 4 个时**必须**标注"最常填错的是第 X 个" |
| ④ 示例 | 每例固定 5 件套：场景一句话 → 数据小表格 → 公式 → 结果 → 一句话记忆点。数据表格**必须**是完整可粘贴的（含表头），**禁止**只给一句光秃秃的公式 |
| ⑤ 注意事项 | ≥ 3 条；每条固定句式：**错在哪 → 为什么会错 → 怎么改**。错误值用等宽红字。**优先收录"不报错但结果错"的坑**（比报错更危险） |
| ⑥ 相关函数 | 3–5 个，每个必须标注关系类型：**易混淆** / **可替代** / **常搭配**，并写一句"什么时候该用它而不是这个" |

### 5.3 禁止事项（内容层面）

- 禁止出现"众所周知""显而易见"这类废话
- 禁止出现未经解释的英文术语缩写（如"通配符"要顺带说明 `*` 和 `?` 怎么用）
- 禁止把示例写成 `=SUM(A1:A10)` 这种无业务含义的占位
- 禁止在注意事项里写"详见微软官方文档"——用户就是不想看官方文档才来的

### 5.4 交付与抽检

- 每批交付 **15 个**，分 4 批走完 55 个
- 每批抽检 **3 个**（第 1 个、中间 1 个、最后 1 个），按 SOP 逐条打分，不合格整批退回
- 甲方每批只确认一次，避免反复打断

## 8. 对 PM-2 两处取舍的复核意见

| 取舍 | 我的意见 |
|---|---|
| 查找与引用类去掉 `LOOKUP` | **同意**。LOOKUP 行为诡异（向量/数组两种形态，且必须排序），用它的人基本都可以改用 XLOOKUP 或 VLOOKUP，硬凑反而增加维护成本。建议把 `LOOKUP` 移出扩展池，或加备注"不推荐新用" |
| 保留 `FILTER` | **同意，但要加一条硬约束**：FILTER 是动态数组函数，**在 Excel 2019 及更早版本不可用**。页面必须显著标注版本要求，且试算区要提示"这是会溢出到多个单元格的公式"。否则甲方照抄后会得到 `#NAME?` 或只显示一个值 |
| 工程、数据库两类不录内容 | **同意**。甲方是非技术职场用户，这两类几乎零使用。保留分类位、不留内容，比硬凑 5 个凑数函数更负责 |

**补充一条建议**：扩展池（51 个）建议**按"甲方点名"而非"我们猜"来排优先级**。§5.4 每批交付时附带一次"你还想要哪个函数"，让甲方自己点，比我们替他决定更准。

## 9. 名词解释补充

| 名词 | 人话解释 |
|---|---|
| TSV | 一种最朴素的表格格式：每行是一条记录，列与列之间用 Tab 键隔开。Excel 认识它，粘贴时会自动一格一格排好 |
| hash 路由 | 网址里带 `#` 的那种链接（如 `xxx.com/#/f/vlookup`）。`#` 后面的部分不会发送给服务器，所以静态网页也能准确定位到内容，不会出现 404 |
| 剪贴板 API | 浏览器提供的"一键复制到剪贴板"功能。部分环境（尤其微信内置浏览器）会限制它，所以要准备降级方案 |
| 动态数组函数 | 新一代 Excel 函数（FILTER、SORT、UNIQUE、SEQUENCE 等），一个公式能自动填满一片单元格。老版本 Excel 没有这个功能 |
| 通配符 | 搜索用的替身符号：`*` 代表任意多个字符，`?` 代表一个字符。要查找字面量的 `*` 本身，得写成 `~*` |
| 1900 / 1904 日期系统 | Excel 内部把日期存成数字。Windows 版默认从 1900-01-01 开始数，老版 Mac 从 1904-01-01 开始数，两边相差 4 年零 1 天——这就是为什么同一份日期在不同电脑上可能差 4 年 |
