## 一、核心目标（Core Objective）

### 1.1 产品定位
一个**以中文为主、英文对照**的 Excel 函数速查网页：用户输入/检索函数 → 查看「用途 + 语法 + 参数 + 示例 + 易错点 + 相关函数」→ 一键复制示例公式 → 必要时**在线试算**验证结果。

- 首个大版本（v1.0）：一次性补全**全部 Excel 函数**，收录 **414 个函数**覆盖 12 大分类；框架与内容模型此前以 60 函数原型完成验证，本版本予以统一整合。

### 1.2 目标用户与价值
| 维度 | 结论 |
|---|---|
| 使用人群 | 非技术背景个人用户为主；需支持生成链接分享给他人查看 |
| 核心价值 | 「查得懂、用得对、可复制、可验证」——把 Excel 帮助文档本地化、结构化、可试算 |
| 差异化 | 中文助记名 + 拼音首字母检索 + 在线试算（高度还原，非微软官方引擎） |

### 1.3 版本与目录约定
- **单一发布目录**：本版本（v1.0）的所有源码与单文件产物均位于同一发布目录；
- 交付物 `delivery/index-v1.html`（文件名沿用工程历史命名，内容即 v1.0 交付物）可双击 `file://` 直接打开、零外链。

## 二、功能需求（Functional Requirements）

### 2.1 必含功能（FR）
| 编号 | 功能 | 说明 / 验收口径 |
|---|---|---|
| FR1 | 函数检索 | 支持 **中文名 / 英文名 / 拼音首字母（abbr）/ 用途关键词（keywords）** 四维搜索；拼音首字母由 `pinyin-pro` 计算，需纯小写（审计正则 `/^[a-z]+$/`）。 |
| FR2 | 函数详情 | 每个函数至少含：一句话用途（oneLiner）、语法（patternCn/En）、参数逐项说明（args）、≥2 个示例（examples，含 dataTsv + 公式 + 结果 + 解释）、常见错误与注意事项（pitfalls，含 errorCode）、相关函数（related）。 |
| FR3 | 在线试算引擎 | core 层纯函数（`evaluateEntry`），对 `calc.enabled:true` 的函数在网页内实时计算；错误用例返回 Excel 错误码（`#VALUE!`/`#DIV/0!`/`#NUM!`/`#REF!`/`#N/A`/`#SPILL!`/`#CALC!` 等）。 |
| FR4 | 一键复制 | 复制示例公式 / 参数片段到剪贴板。 |
| FR5 | 站内编辑 + 本机存储 | 用户在网页内直接编辑内容，改动存 `localStorage`；支持导出备份（fileIo / backup / repository）。**不做登录账号**。 |
| FR6 | 可分发 / 可分享 | 单文件 HTML（`vite-plugin-singlefile`），JS+CSS+favicon 全部内联，**双击 `file://` 直接打开、零外链**；可任意拷贝、可生成分享链接。 |
| FR7 | 分类导航 | 沿用 Excel 官方 12 分类体系；导航 / 首页常用榜 / 搜索结果联动。 |

### 2.2 内容维护约定
- 团队出初稿（每函数一个 `FunctionEntry` sample 文件），用户在网页内精修。
- 新函数默认 `calc.enabled:false`（仅展示文档，不接计算引擎），逐类启算。

### 2.3 已披露风险（须如实告知用户）
在线试算为「**高度还原**」而非微软官方引擎，边缘情况（区域设置、日期序列号、浮点精度）可能有细微差异，试算区需标注「**结果以 Excel 实际为准**」。

## 三、技术约束与边界条件（Constraints & Boundaries）

### 3.1 运行环境约束
| 约束 | 影响 / 对策 |
|---|---|
| 沙箱 shell 是 `sh`（dash）不是 bash | 避免 `PIPESTATUS`、数组 `${a[0]}`、`>file` 重定向；取输出用 `| tail`。 |
| `vite build` 清空 outDir 触发 safe-delete 回收站钩子崩溃 | `vite.config.ts` 设 `emptyOutDir:false`；outDir 指向工程根之外 `../.tmp/dist`，单文件产物每次覆盖写入。 |
| 子代理 429 限流（按窗口重置） | 即使报告 "failed" 也要先核对**磁盘真实文件**；缺失由主理人补写；子代理可能「虚报交付」，集成前必 `ls` + 跑真实 spec。 |
| Node 二进制 | 用受管 Node：`C:/Users/LENOVO/.workbuddy/binaries/node/versions/22.22.2-2/node.exe`；tsc/vitest/vite 经该路径调用。 |

### 3.2 架构约束
- React 18 SPA + `react-router-dom` **hash 路由**（`createHashRouter`，`file://` 下天然可用，无需服务器）。
- 数据层与界面层分离（`src/data` vs `src/ui`），便于将来转 App。
- 无后端、无账号；编辑态存 `localStorage`，可导出/导入备份。
- 单文件交付：`SINGLE_FILE=1` 启用 `vite-plugin-singlefile`，失去按分类懒加载收益，但本地 file:// 下整体更快、更省事。

### 3.3 数据模型约束（单一数据源）
- **`catalog.json` 是单一权威数据源**，由 `packs/*.ts` 注册表经 `scripts/regen-catalog.mjs`（`npm run gen:catalog`）反推生成。
- **新函数只需进对应 `packs/<cat>.ts` 的 `default` 导出**，即自动进 catalog（无需手改 catalog.json）。
- 拼音 `abbr`/`pinyin` 的**权威来源是 `pinyin-pro` 由 `zhName` 计算**，经 `gen:pinyin → sync-abbr` 回流 sample 与 catalog，禁止人工手填不一致值。
- `dotted id`（如 `erf.precise`）：TS 变量名须 sanitize（`erfprecise`），pack key 与 `id` 字段保留点号（引号键 `'erf.precise'`）。

### 3.4 计算边界
- `buildCalcSheet`（`src/core/ref.ts`）只看 `sampleTableId` / `examples[0].dataTsv` / `examples[0].tableId`；**纯标量函数（只从 args 取参）三者皆无 → 须对 `enabled` 条目返回空 Sheet `{anchor:'A1',header:[],rows:[]}`**，否则 `evaluateEntry` 在调 handler 前就 `fail(#REF!)`（B14 NPV 曾踩此坑）。
- handler 返回 `ok(value,display?,warning?)` / `fail(make(ERROR_CODES.X,reason,fix))`；`expect` 铁律——错误用例 `expect=错误码`，正确用例 `expect=干净 display 串`。详见 `docs/CALC_HANDLER_CONTRACT.md`。

## 五、关键流程（Key Flows）

### 5.1 新增函数批次流水线（SOP，含正确拼音顺序）
> 经验证的正确顺序（`gen:catalog` 必须 **最后** 跑，且 sync-abbr 须在其前把新 abbr 镜像回 sample，否则会被 stale sample 覆盖）：

```
① gen:catalog   → 把改动（含新 zhName）推入 catalog（结构/zhName 权威）
② gen:pinyin    → 由 zhName 经 pinyin-pro 计算 abbr/pinyin 写入 catalog
③ sync-abbr     → 把 catalog 的 abbr/pinyin 回写 sample 文件
④ gen:catalog   → 最终重生成（此时 sample 已含干净 abbr，catalog 幂等保持）
⑤ tsc --noEmit  → 0 错误
⑥ vitest run    → 全绿（含 audit-consistency 期望 414/0/0/0）
⑦ build:deliver → SINGLE_FILE=1 vite build → finalize-cp → delivery/index-v1.html
```

**必踩 4 坑（已固化进生成器，复刻照做）**
1. 每个 sample `.ts` **首行必须有** `import type { FunctionEntry } from '@/types';`（否则 tsc `Cannot find name 'FunctionEntry'`）。
2. `gen-pinyin.mjs` 对 pinyin-pro 分支必须 `.toLowerCase()`，否则 `F分布`→`Ffb` 违反审计。
3. `dataTsv` 等文本含 `\t`/`\n`/`\r`，序列化进单引号字符串须转义 `\\t`/`\\n`/`\\r`，否则 esbuild `Unterminated string literal`。
4. dotted id 的 TS 变量名 sanitize；`zhName` 含 `/` 会产生非纯小写 abbr（如「取前几行/列」→`qqjh/l`），应改为「或」字（→`qqjhhl`）。

### 5.2 在线试算调用链
```
UI 输入 args
  → evaluateEntry(entry, args, resolver)        [registry.ts 唯一入口]
      → buildCalcSheet(entry)                   [ref.ts：有 dataTsv 建表；enabled 标量函数返回空 Sheet]
      → HANDLERS[fnId](ctx)                     [纯函数 handler]
          → 读参/读表(cellValue/sliceSheet) → 计算
      → 返回 ok(value,display) / fail(ERROR_CODES.X)
  → UI 渲染结果或错误码
```
- 通用验收 `calc-cases.spec.ts` 遍历**所有 `enabled:true`** 样本的 cases，断言 `display`/`错误码`，是上线前硬门槛。

### 5.3 构建与交付
`npm run build:deliver` = `build:single`(tsc + `cross-env SINGLE_FILE=1 vite build` → `../.tmp/dist`) + `finalize-cp.mjs`(→ `delivery/index-v1.html`)。产物须自检：零外链、含 `id="root"`、新分类进导航、体积确有增长。

### 5.4 验收流程（红灯/绿灯）
| 关卡 | 命令 | 绿灯标准 |
|---|---|---|
| 类型 | `tsc --noEmit` | 0 错误 |
| 单元/集成 | `vitest run` | 全文件全测试通过（现 36 文件 / 140 测试） |
| 一致性审计 | `audit-consistency.spec.ts` | 解析失败 0 / catalog 偏离 0 / 问题 0（现 414/0/0/0） |

## 八、风险与已知坑（Risks & Pitfalls）

1. **环境**：沙箱 `sh` 非 bash、`vite` 清空 outDir 触发 safe-delete 崩溃、`emptyOutDir:false` 绕过；Node 用受管路径。
2. **限流**：子代理 429 后可能虚报交付——**以磁盘文件 + 真实 spec 为准**，不轻信报告。
3. **流水线顺序**：`gen:catalog` 必须最后跑且 sync-abbr 在其前；`zhName` 含 `/` 会污染 abbr。
4. **计算**：纯标量函数须 `buildCalcSheet` 返回空 Sheet，否则 `#REF!` 误杀；易失函数（today/now）试算断言需跳过展示值。
5. **一致性**：`catalog.json` 是权威源，经 pack 反推；手改 sample 的 abbr 会被流水线覆盖，以 pinyin-pro 为准。
6. **版本约定**：本版本（v1.0）为单一发布目录，源码与交付物同处 `XLFuncs-release/`。
